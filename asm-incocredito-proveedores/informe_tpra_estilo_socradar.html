Score heurístico 0–100 y grado A–F: cada dominio recibe un puntaje basado en los factores que el escáner puede verificar de forma pasiva. El promedio de todos los dominios determina el grado general. La escala sigue el modelo de SecurityScorecard:

  • A (≥90) — postura excelente, controles sólidos en todos los ejes medibles.
  • B (75–89) — buena, con oportunidades menores de mejora.
  • C (60–74) — aceptable, pero con carencias que deben revisarse.
  • D (45–59) — deficiente, múltiples controles ausentes o mal configurados.
  • E (30–44) — pobre, riesgo elevado en varios dominios.
  • F (<30) — crítico, requiere atención inmediata.

Factores evaluados en este informe:

  • Configuraciones DNS — SPF (hard-fail), DMARC (reject/quarantine), DKIM, DNSSEC, DANE/TLSA, registros MX y NS, CAA, MTA-STS, TLS-RPT, BIMI.
  • Certificados SSL/TLS — versión negociada, TLS 1.3 exclusivo, vigencia, emisor, SAN, serial.
  • Puertos abiertos — disponibilidad de servicios en 80 (HTTP) y 443 (HTTPS).
  • Cabeceras de seguridad HTTP — HSTS, CSP, X-Frame-Options, X-Content-Type-Options, Feature-Policy/Permissions-Policy, Expect-CT, X-Permitted-Cross-Domain, Server, X-Powered-By, detección de CDN/WAF (Via, CF-Ray, X-CDN).
  • Superficie de subdominios — descubrimiento por fuerza bruta DNS prefijos y fuentes OSINT pasivas (crt.sh, BufferOver, ThreatCrowd).
  • Geolocalización de IPs — país asociado a las direcciones IPv4 del dominio.
  • Reputación de IPs — consulta a DNSBL (Spamhaus ZEN, Barracuda, SpamCop, SORBS, CBL) para detectar IPs listadas como maliciosas o comprometidas.
  • Malware detectado — consulta a URLhaus (Abuse.ch) para verificar si el dominio ha sido reportado como distribuidor de malware.
  • Vulnerabilidades expuestas — detección de tecnologías desde cabeceras HTTP (Server, X-Powered-By) y consulta a la base OSV.dev para identificar CVEs asociados a las versiones detectadas.
  • Fugas de credenciales — consulta a leak-lookup.com para identificar si el dominio aparece en breaches conocidos (requiere variable de entorno LEAK_API_KEY).
  • Riesgos de phishing / typosquatting — generación de variantes del dominio (cambio de TLD, caracteres adyacentes, omisiones, prefijos comunes) y verificación DNS para detectar posibles dominios falsos activos.
  • Patching cadence — consulta a endoflife.date para las tecnologías detectadas en cabeceras (Server, X-Powered-By) y determina si la versión está EOL, próxima a EOL o vigente.
  • Riesgo de terceros y supply chain — extracción de dominios de terceros desde cabeceras CSP y scripts externos en la página principal, con verificación DNS de resolución.
